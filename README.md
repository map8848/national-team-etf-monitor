# 国家队 ETF 申购看板

**一句话：** 按交易所每天公布的 ETF 份额，算出 22 只宽基 ETF 当天总共被买走了多少、卖掉了多少；再用半年报里的实名持有人名单对一下，把哪些是真的数据、哪些是我们推出来的、误差有多大，全摆出来。

**本页全是公开数据算的，不是官方公布的。不是投资建议。**

## 为什么不叫「国家队持仓看板」

每天能拿到的只有份额变动。份额变动是全市场一级市场申赎相抵后的**匿名净额**——做市商、套利盘、机构、个人全都混在一起，无法区分汇金还是别人。把「份额涨了」直接写成「国家队买了」是同类项目里最普遍的错。

所以这里把两行数字分开：

- **全池净申购（匿名净额）**：实测，来自交易所份额日报。
- **疑似入场强度（估算）**：0–100 的启发式打分，命中哪些条件、哪些条件还没接，点一下能逐条看。

季度实名持仓不是并列的第二个页面，而是**对照层**：给日频推测提供锚点，并把对不上的地方直接列出来。

## 界面上三层标注怎么来的

| 层 | 内容 | 界面处理 |
| --- | --- | --- |
| 实测 | 交易所份额、收盘价、报告期实名持有人、官方公告 | 硬数据，不加标签 |
| 估算 | 净申购强度、同步性、连续天数、逆势命中 | 必带「估算」角标，可展开每条依据 |
| 对照 | 半年报实名锚点 vs 日频累计 | 对不上的数量、校验偏差、归因缺口直接列出 |

## 怎么算的（完整说明）

1. **每只 ETF 算金额**：`(今天份额 − 昨天份额) × 今天收盘价`，22 只加起来就是全池当天净申购（亿元）。不能把不同 ETF 的份额先加起来再乘一个价格——每只单位净值不一样。
2. **收盘价估净值**：申赎按基金单位净值成交，我们用二级市场收盘价代替，折溢价没校正。
3. **份额第二天才出**：份额当日数据次日披露，序列日期是份额披露对应的行情日，价格对齐到同一交易日。
4. **两个口径不能相加**：ETF 底层仍是股票，个股前十大流通股东口径与 ETF 份额口径重复计算。本页不含个股。
5. **主体归一**：报告里的股东名称变体极多，`config/entities.json` 用 11 条带排除规则的列表归到四层。纯关键词匹配会把「同瑞汇金3期私募」「…ETF联接基金」误判成国家队，本页一律排除。
6. **份额跳变**：单日大幅变动也可能包含份额折算、合并等非申赎因素，本页如实呈现，不替用户删掉。
7. **大盘对照**：主图同一张 SVG 内上下双面板——上方是上证指数或沪深300 的日 K（红涨绿跌：收涨红色空心、收跌绿色实心），下方是当天净申购柱与区间累计线，共用交易日历与悬停竖线。指数行情比份额日报多 1–2 个交易日，图上按份额交易日历对齐。腾讯 fqkline 与东财 push2his 的 OHLC 逐日比对，最大差 0.01 点。右上可切时间范围（近 30 / 90 / 半年 / 全年），只改变画出来的天数；它和情景表的统计窗口是两组独立控件，因为最近 20 个交易日还没有后 20 日结果，两者样本不同。
8. **相关不等于归因**：图下的相关系数由「当日指数涨跌幅 × 当日全池净申购」逐日配对计算，包含份额折算跳变日；「逆势日」只表示指数收跌且当日净申购为正，不表示买方身份。对照读数按全年算，不随上方时间范围切换。
9. **历史情景对照**：按第 t 日的条件（全部交易日 / 大额净申购 ≥ P80 / 大额净赎回 ≤ P20 / 逆势申购 / 普通日）分组，统计其后 5、10、20 个交易日收盘的组内中位数与上涨天数占比，窗口可选近 30 / 90 日 / 半年 / 全年。窗口取「可用候选的最后 N 个」，因为最近 20 个交易日还没有 t+20 结果；阈值 P80/P20 按每个窗口自己重算。各行条件可能重叠，不是互斥分桶。这是历史条件分布的描述，不是预测——样本只有一个完整年度，短窗口内每组可能只剩几个样本，组间差异极易落在噪声内。
10. **方向读数**：把最新一个交易日按「大额申购 → 大额赎回 → 逆势申购 → 普通日」的优先序归入上表某一行，再比较该行与全样本的后 20 日中位数和胜率：中位数高出 0.3 个百分点以上且胜率高出 5 个百分点记为「偏多」，反向记为「偏弱」，其余为「中性」。这是位置读数，不是对未来涨跌的判断；样本不足 10 个时页面会直接标注。

页面里的 `N1`–`N13` 脚注编号都指向「口径与误差」章节，每条都写清了算法与边界。

## 数据从哪来的

| 来源 | 用途 | 许可 / 说明 |
| --- | --- | --- |
| 上海证券交易所 ETF 份额日报 | 跟我们算的逐天对一下 | 公开数据，`TOT_VOL` 单位万份 |
| [H-Jett/etf-radar](https://github.com/H-Jett/etf-radar) 的 Pages 快照 | 日频份额序列、收盘价、实名持有人锚点 | MIT |
| 腾讯证券 fqkline | 上证指数、沪深300 日 K（主源） | 公开接口，未复权 |
| 东方财富 push2his K 线 | 指数日 K 双源比对；push2 行情另用于 510300 份额校验 | 公开接口 |

指数日 K 的两路抓取与上交所份额校验都标为 `optional`：抓不到时只告警，不阻断日更，沿用仓库里已提交的快照。理由是校验层与对照层都不该成为主数据可用性的单点故障——GitHub Actions 境外出网抓国内行情接口可能失败，`query.sse.com.cn` 对境外机房 IP 会直接返回 403。

三方交叉校验：`sse/2026-11-10` 里 510300 的 `TOT_VOL = 4634238.77` 万份 = 46,342,387,700 份；本页序列末值 46,342,387,700 份；东财 `stock/get` 的 `f84 = 46,342,387,712` 份。差异来自浮点取整，不是口径分歧。

标的池取宽基行业 id:0 的全部 22 只，选择标准是「有 2025-12-31 实名前十大持有人锚点可回溯」。588000、512050、159338 等未纳入该库的核心宽基不在池内，因此本页数字**不代表全市场宽基 ETF**。

## 怎么跑起来

```bash
# 采集公开快照（零依赖，只需 Node 18+）
node scripts/gather.mjs

# 算出派生数据 → data/dashboard.json 与 data/dashboard.js
node scripts/build.mjs

# 或一步到位
npm run refresh

# 冒烟自检：用最小 DOM 执行 app.js，确认十个数据区块都能渲染
npm run smoke
```

然后直接双击 `index.html` 即可打开（用 `<script src>` 加载数据，不依赖本地服务器、不依赖构建、不依赖任何前端框架）。部署到 GitHub Pages 时把 Pages 源设为仓库根目录即可。

日更由 `.github/workflows/daily.yml` 在每个工作日北京 17:23 / 19:23 / 21:23 / 23:23 四个错峰时段执行采集 + 计算 + 提交（GitHub 定时任务在高负载时段可能延迟数小时甚至漏跑，多档重试保证当天数据不丢；上游份额日报约 16:13 生成，四档均晚于生成时间；任一时段命中新交易日即提交，其余因交易日未前进而自动跳过）。

首次发布用 `scripts/publish.mjs`（零依赖，走 GitHub REST API，不需要 git 出网）：

```bash
GITHUB_TOKEN=<你的 PAT> node scripts/publish.mjs
```

脚本建公开仓库、上传工作区全部文件、开启 Pages、把 Actions 默认权限设为写、触发一次日更，最后回读站点地址。PAT 也可以放在工作区 `.github-pat`（已写进 .gitignore），脚本完成后会删除该文件。classic PAT 需要 `repo` 与 `workflow` 两个 scope；fine-grained PAT 需要对应仓库的 Contents / Workflows / Pages / Actions / Administration 读写权限，且 `POST /user/repos` 不受支持，需先在浏览器建好同名空仓库。

用 REST API 创建的初始提交与本地 `git` 历史不同 sha，日更由远端 Actions 自己提交；若之后想在本机继续用 git 推拉，先 `git remote add origin <远端地址>`，再 `git fetch --depth=1 origin && git reset --hard origin/main`。

后续改动上线用 `scripts/sync.mjs`（同样零依赖、走 REST API，不需要 git 出网）：

```bash
GITHUB_TOKEN=<你的 PAT> node scripts/sync.mjs
# 先看会传哪些文件、不联网
node scripts/sync.mjs --dry-run
```

它读远端 `main` 的当前 head，把工作区文件全量打成新 tree，基于该 head 建一个提交并移动分支引用；不会覆盖 Actions 机器人已提交的历史。push 会触发 Pages 重新部署。脚本只做同步，不重建仓库、不改 Pages 设置。token 同样只在内存中使用。

## 目录

```
index.html                 静态页面（自绘 SVG 双面板图表，零依赖）
styles.css                 样式
app.js                    渲染逻辑
config/entities.json       主体分层名单（11 条规则 + 排除项）
config/pool.json           核心宽基标的池与边界说明
config/events.json         公告 / 政策 / 报道（人工核实后追加，每条带出处）
scripts/gather.mjs         采集：交易所日报 + Pages 快照 + 指数日 K → data/raw/
scripts/build.mjs          计算：逐只净申购 / 大盘对照 / 强度分 / 校准 → data/
scripts/smoke.cjs          冒烟自检（最小 DOM 模拟，零依赖）
scripts/publish.mjs        一次性发布：建仓 / 上传 / 开 Pages / 触发日更
scripts/sync.mjs           后续同步：基于远端 head 推一个新提交
data/raw/                  原始快照（41 个 JSON，含 4 个指数日 K 与 8 个上交所校验）
data/dashboard.json        派生数据（供其他消费者）
data/dashboard.js          同一份数据，供页面直接 <script> 引入
.github/workflows/daily.yml 每日更新
```

技术栈说明：原计划 Vite + React + ECharts，实际落地为零依赖静态页 + 自绘 SVG。这个看板只有 206 个交易日 × 22 只标的，不需要框架；去掉构建步骤后页面可以双击打开、Pages 直接托管，图表也能精确按「静音网格、等宽标签、单一强调色」的规范来做，不会带图表库的默认样式。核心架构（纯静态站 + JSON 数据、无后端）不变。

## 已知边界

- 最新实名锚点是 2025-12-31，**归因还没闭合**；22 只里有 12 只出现「锚点份额若不变则隐含占比超过 100%」，这说明期间必然赎回过，但匿名日频数据无法判断其中哪一部分属于国家队。需等 2026 年报披露才能回测。
- 深市份额来自数据源的深交所日报，本版未做独立回源校验；上交所标的做了逐日校验。
- 未接入分钟级成交、IOPV、两市成交额与融资余额，因此「尾盘放量」「折溢价」「成交额分位」这几条依据明确标为未接入，不参与打分。
- 事件流只作背景标注，不进入强度打分。数据在 `config/events.json`（当前 10 条，2025-04-08 → 2026-11-12），**日更只读不抓**：新闻与公告没有可靠的自动采集通道，自动抓取会把转载、重复与未核实内容带进本页，因此改为人工核实原文后追加，每条必须带可点开的出处。
- 页面按模块分屏：左侧导航一次只显示一个模块，`#calibration` / `#method` / `#sources` 默认 `hidden`，无 JS 时只有日频台账可见。脚注 `[N1]`–`[N13]` 位于「口径与误差」模块内，点击时会先展开该模块再定位到对应条目，因此跨模块跳转不会落到隐藏区域。
- 大盘对照只做同日并列观察与描述性相关，不做因果推断；东财 K 线接口偶发不可达时沿用已提交的快照，会在 `data/raw/` 里留下旧日期的文件。
- 数据快照截至 2026-11-12，交易日数 207。

## 跟别人的区别

GitHub 上同类项目（OrangesHuang/Resonance、kitaki-Ciallo/etf-national-tracker、digger-yu/etf、H-Jett/etf-radar 等）大多把份额变化直接命名为「国家队买入」，且没有一家把「半年报实名前十大持有人 → 回测日频推测」的误差闭环做进界面。本页把口径、未接入项、冲突数与归因缺口全部摊开，并把主体归一字典作为第一天就建的配置文件。

代码不复制任何同类仓库；数据来自 MIT 许可的公开快照与交易所公开日报，已在上方署名。
